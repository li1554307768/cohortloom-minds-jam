# Rules Snapshot

This is the operating contract for CohortLoom.

## Product rules

- Start from weekly engagement metrics.
- Turn the metrics into one falsifiable audience hypothesis.
- Require creator approval before any memory write is prepared.
- Run one bounded 7-day manual experiment.
- Define success and stop conditions before the experiment starts.
- Schedule a due review.
- Keep the loop reviewable and auditable.

## Hard exclusions

- No inbox behavior
- No content-idea generation as the end product
- No correction-tool behavior
- No social scheduling
- No outreach or contact automation
- No auto-posting
- No blind retry after transport uncertainty

## Minds rules

- Store only creator-approved hypotheses.
- Recall only from the same Mind lineage.
- Use a fresh session for plan and review stages.
- Do not repeat the hypothesis body in the due-review request data.
- Keep the due-review request narrow: experiment reference, due label, observed result, success condition, stop condition.
- Reject any plan that contains outreach language such as DM, cold email, mass message, auto-post, or follow users.

## Evidence rules

- Synthetic demo data must stay labeled synthetic.
- Local tests do not prove live continuity.
- A placeholder video report is not a rendered video.
- A claimed revenue number is not evidence unless backed by external proof.

## Safety rules

- Pause is a real kill switch.
- Explicit human action is required for any Minds send.
- The credit floor must stay at 10 or above.
- Secret scans and license checks are part of the release workflow.

## Claiming rules

When writing any external copy, use the following pattern:

- verified facts as facts
- pending items as pending
- synthetic items as synthetic
- unverified live proof as unverified

That keeps the hackathon submission honest and easy to audit.
